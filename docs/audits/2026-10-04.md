## 项目定位与已定约定

- **这是个人网站，不是 terminal emulator。** spec [§1.1](../../terminal_personal_website_master_spec.md) "Terminal-inspired, not terminal-emulated" 和 §26 "Explicit non-goals" 已经写明，不做 shell 模拟，也不做浏览器端文件系统。
- **约定优先于兼容。** 遇到奇怪的输入时，在构建阶段明确拒绝，不在运行时增加字符串处理。优先选择能删代码的方案，避免大的技术负担。
- **已决定：URL 路径只允许 ASCII。** 文件名和目录名不允许中文、空格和 URL 保留字符；中文写在 frontmatter 的 `title` 里。具体规则见待办 2。
- **已决定：空目录不生成页面。** 只有含已发布文档的目录才存在；目录里只有 `index.md` 也算含文档。见待办 3。
- **已决定：`index.md` 保持可选，不做按目录切换主题或颜色。** 默认全部自动生成，需要改名称、介绍、排序或整体草稿时再写 `index.md`。理由见附录"`index.md` 的定位"。
- **已决定：模板里所有个人文案都移入 `site.json`**，包括 wordmark 后缀（`’s space`）、说明文字、页脚、404 标题，以及语言和日期地区。改这些只需要换配置里的字符串。见待办 17。
- **已决定：删除 `hidden`，统一用 `draft`。** 不想公开的内容一律不构建，网址返回 404。旧的 `hidden: true` 会让构建报错并提示改用 `draft`，避免误以为页面被隐藏、实际却已发布。
- **已决定：许可证。** 代码 MIT；`src/content/` 和 `site.json` 中的个人资料保留所有权利；第三方字体和 OMP 主题保留各自原有的许可。
- **测试环境：** 所有构建和测试命令都通过 `nix-shell shell.nix --run '…'` 运行，或先进入 `nix-shell` 再执行 npm；不安装全局包，也不下载 Playwright 浏览器。

## A. 内容约定（待办 1–3）——✅ 本轮已完成，以下保留问题描述供追溯

这三项一起实现，改动集中在 [site-index.ts](../../src/lib/navigation/site-index.ts)、[tree.ts](../../src/lib/content/tree.ts)、[BaseLayout.astro](../../src/layouts/BaseLayout.astro) 和 [astro.config.mjs](../../astro.config.mjs) 四个文件。同时要更新 README 和 spec。完成后，"文件夹即网站"可以用一句话说清：

> **合法命名的 `.md`／`.mdx` 文件就是页面，含有页面的目录就是栏目，其余一律忽略。**

### 1. hidden 页面全文随每个页面发布（P1）

BaseLayout 第 50 行把整个 `entries` 数组内联进每个页面的 `site-data`，其中包括 hidden 条目的标题、路径和 `searchText`（即全文）。界面上的列表、搜索和补全都会过滤 hidden，所以页面看起来正常；但查看任一页面的源代码，就能读到 hidden 页面的全部内容。另外，`sitemap()` 没有 filter，hidden 页面也会提交给搜索引擎。现有 build 测试只检查 `site-data` 之前的 HTML，还要求 hidden 条目留在数据中，所以没有覆盖这个问题。你目前没有 hidden 页面，因此尚未实际泄露。

修法：

1. 内联数据只保留非 hidden 条目；当前页面若本身是 hidden，则只保留它自己。
2. 用 `sitemap({ filter })` 排除 hidden 路径。
3. 取消 README 中"`cd`／`open` 可访问 hidden 精确路径"的承诺。hidden 的含义改为"只有知道 URL 的人能访问"。
4. build 测试改为断言：没有任何 HTML 页面和 sitemap 包含 hidden 页面的正文或路径。

README 还应写明：hidden 不是访问控制，真正私密的内容不要放进公开构建。

### 2. 内容命名约定与构建校验（P1）

`c#-tips.md`、`why?.md` 会被 Astro glob loader 当成 URL 片段和查询字符串处理，读取失败后页面静默消失，构建仍然成功。`#`、`?`、`%` 即使能生成页面，在 `href` 和 `location.assign()` 中也会被浏览器解释成 URL 语法。目前代码还为空格和中文做了引号补全（[autocomplete.ts](../../src/lib/terminal/autocomplete.ts) 第 20–33 行）和 URL 解码；大小写不同的同名目录在 macOS 默认文件系统上也会冲突。

已定规则：

```text
目录名、文档文件名（不含 .md/.mdx）：  ^[a-z0-9]+(-[a-z0-9]+)*$
例：  notes/machine-learning/attention-is-all.md      ✓
      notes/Machine Learning/注意力.md                 ✗  构建失败，并列出所有违规路径
以 . 或 _ 开头的文件和目录：不参与路由，也不检查命名
图片等非 md/mdx 文件：不生成路由，命名不受此约束
```

实现位置：`site-index.ts` 的 `contentDirectories()` 已经在遍历真实文件系统。把它扩展为同时列出 md/mdx 文件并检查命名，一次性收集所有违规项后抛出错误即可，大约十几行代码。校验必须放在这里，因为非法文件在进入 `buildContentTree()` 之前就已经被 glob loader 丢掉了。

采纳后可以删除的东西：

- 补全中的空格引号逻辑；
- `test:build`、`test:dev` 中的中文和空格路径用例，改为"构建会拒绝"的用例；
- README 中支持中文和空格路径的说明。

页面标题仍可以写中文。

### 3. 不含文档的目录被当成栏目（P1，与 2 一起修）

`tree.ts` 第 113–118 行会把所有不含 md/mdx 的目录登记为空栏目，这是上一轮刻意实现的"空目录可访问"。实际后果：

- `blog/images/` 这类图片目录会以 "Nothing here yet" 空页出现在列表、`ls`、搜索和 sitemap 中；
- `.obsidian/` 这类编辑器目录会出现在首页导航；
- 在 `about.md` 旁边放一个 `about/` 图片目录会导致构建失败，而这恰好是 README 推荐的"图片放在 Markdown 旁边"的写法。

已决定：**目录只有在含有已发布文档时才存在**（`index.md` 也算），这推翻了上一轮"空目录可访问"的做法。

修法：

1. 删除空目录页，以及 `tree.ts` 第 113–118 行的目录扫描逻辑。目录节点只从文档的父路径推导出来，这部分逻辑已经存在。
2. 删除 `[...path].astro` 中的 "Nothing here yet" 空态。目录如果只有 `index.md`，就只显示介绍正文。
3. 图片目录、`.obsidian` 自然不会出现，`about.md` + `about/` 也不再冲突。
4. 同步修改 README 和 `test:build` 中的空目录用例（改为断言不生成）。

`site-index.ts` 的文件系统遍历仍然保留，但只用于待办 2 的命名校验。

## C. 内容体验（待办 6–8）——✅ 本轮已完成，以下保留问题描述供追溯

### 6. RSS 硬编码 `/blog/`（✅ 已完成）

[rss.xml.ts](../../src/pages/rss.xml.ts) 第 6 行只收录 `/blog/` 下的文档，这是文件树改造后残留的唯一一处栏目硬编码。把 `blog/` 改名，或在 `research/` 中发布带日期的文章，RSS 都会静默不收录。

修法：在 `site.json` 中加 `"feed": ["/blog"]`，列出进入 RSS 的目录。同时给 `rss()` 传入 `trailingSlash: false`。`@astrojs/rss` 默认输出 `/blog/x/`，与 canonical 的 `/blog/x` 不一致；而 Caddy 配置了 `disable_canonical_uris`，两种地址都能打开，于是同一页面有两个 URL。

### 7. 版式由目录深度决定（✅ 已完成）

[\[...path\].astro](../../src/pages/[...path].astro) 第 27–29 行的逻辑是：根目录文档用 `PageLayout`（没有日期、标签、目录、更新时间、项目链接），更深的文档用 `ArticleLayout`。同一篇文章移动位置后，显示方式就变了。

修法：**文档一律用 `ArticleLayout`，目录一律用 `PageLayout`。** About、Uses 没有日期，元数据区为空即可。

### 8. 站内链接约定与死链检查（✅ 已完成）

写 `[x](./paper.md)` 时，输出仍是 `./paper.md`，线上会 404。写成相对路径 `paper` 时，结果取决于访问地址是否带尾斜杠。不建议写 remark 插件去改写链接。

修法：

1. README 写明约定：**站内链接使用以 `/` 开头的绝对路径**，例如 `[x](/research/paper)`。
2. 在 `check:release` 中加入死链检查：扫描 `dist/**/*.html` 中以 `/` 开头的 `href`／`src`，确认目标文件存在。顺便检查部署 base（待办 11）和输出配置。示例内容和空联系方式只提示、不报错，允许有意保留。

## 待办 26：hidden 的含义（✅ 已决定并实施：方案 A）

静态网站上，"输入网址也打不开"只有一种实现方式，就是不生成这个页面，而这正是现有的 `draft: true`。要"生成了、但只有授权的人能看"，就需要服务器端访问控制（例如在 NixOS 模块中为某个路径加 Caddy `basic_auth`）。这样做只适用于自有服务器，GitHub Pages 等静态托管做不到，而且会引入密码管理。

可选方案：

- **A. 删除 `hidden`，统一用 `draft`。** 不想公开的内容一律不构建。可以删掉 `publicEntries`、hidden 继承、`noindex`、sitemap 过滤和相关测试，代码最少。代价是失去"不公开列出、但可以把链接发给别人"的用法。
- **B. 保持现状。** `hidden` 是"不公开列出"，`draft` 是"不构建"，两者并存，README 已写明 hidden 不是访问控制。
- **C. 自有服务器上的密码保护。** 在 Caddy 上给某个目录加 basic auth，开销最大，只在 NixOS 部署下有效。

你选择了 A，已在第三批实施。

## 附录：`index.md` 的定位

**默认不需要 `index.md`。** 没有它时，目录会自动生成：名称由目录名推导（`machine-learning` → Machine Learning），介绍为 `Explore ~/路径.`，正文是子项列表，排序为目录在前、文档按日期或字母。

**写 `index.md` 只为了以下几件事**（文件也可以是 `index.mdx`）：

| 能做的 | 说明 |
| --- | --- |
| `title` | 显示名；ASCII 路径下给目录起中文名的唯一方式 |
| `description` | `ls`、列表、搜索、meta 中的介绍文字 |
| `order` | 在父目录中的排序 |
| `draft: true` | 整个子树不发布 |
| `show_children: false` | 不在正文下方列出子项 |
| 正文 | 目录首页的介绍文字；`index.mdx` 可以使用 MDX 组件 |

| 不做的 | 理由 |
| --- | --- |
| 按目录切换主题或颜色 | 主题是访客自己的选择，保存在 `localStorage` 中并作用于全站。如果按目录覆盖，需要定义"访客选择与目录设定谁优先"、保证五套主题的明暗对比度、处理 mobile 配套，复杂度不划算，而且会让访客的选择看起来失灵 |
| 用 HTML 或模板替代 `index.md` | 违背"内容即文件"的约定，也会引入布局系统 |
| 设定会继承给子页面的样式 | 同上 |

如果某个目录首页确实需要一点特别的视觉效果，`index.mdx` 的正文本来就可以写组件或带 class 的元素。这只影响那一页的正文，不影响主题，也不需要改底层。

**结论：保留 `index.md`，保持可选。** 它是唯一不额外增加配置文件、又能给目录加元数据的方式；删掉它，就要另造 `section.json` 一类的东西。大多数目录不需要写；只有想改显示名、介绍、排序，或者想整体草稿／隐藏时才写。

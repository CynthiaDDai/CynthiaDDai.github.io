## 2026-10-03 本轮修复与 mobile 重构

- **P1／公开地址**：显式加载 `.env` 与当前模式的环境文件；进程注入值优先。正常 `astro build` 会选择 production 模式，不依赖 Vite 提前设置 `NODE_ENV`。非法 origin 构建失败，`npm run check:release` 拒绝占位和本机地址。
- **P1／嵌套目录**：统一索引补全所有已发布文章的父目录，生成可访问的目录页。普通列表、面包屑、返回链接、`ls`、`cd ..`、补全和搜索共享这些条目；草稿不生成目录，文章与目录路径冲突会报错。
- **Mobile／首页与导航**：直接打开 index；navigate、tools、recent、friends 都可点。内容页使用 `index +`、紧凑路径栏和触摸按钮，普通链接无 JavaScript 也可用。
- **Mobile／命令**：顶部下拉面板提供可点选的 `help`、`fastfetch`；导航、搜索、主题和友链有各自的直接入口，不重复出现在命令快捷列表。结果单次替换、可点选清空；输入框需主动展开，提供触摸补全与运行按钮。
- **Mobile／主题**：扫描 `src/themes` 的直接子目录，每个目录要求恰好一个 OMP 文件，`theme_mobile.json` 可选。现有主题仅 Storm 有 mobile 配套，另新增同结构的 Storm Day，日间版只换颜色盘；`1_shell`、`if_tea`、Paper 没有新增 mobile 文件。缺少配套时使用主题自身网站颜色与简单路径 prompt，后续主题的 mobile 设计由作者负责。
- **Mobile／阅读与无障碍**：优化文章、列表、目录、表格、公式、fastfetch 和搜索的触摸呈现；关闭面板返回焦点，支持 Escape、背景点按和滚动。可横向滚动的代码、表格、公式在静态 HTML 中可获得焦点。
- **验收入口**：默认浏览器测试构建后使用 production preview，并等待交互初始化。生产构建强制刷新内容缓存，避免 Markdown 插件变更后复用旧 HTML。README 已更新目录规范、mobile 文件接口、操作和测试方式。

## 已解决 3

内容系统现为单一递归 Astro collection → `buildContentTree()` → 统一内容树及其平面投影。Root Markdown、任意栏目、嵌套目录、空目录、explicit `index.md` 和 generated directory index 都通过同一个 catch-all 路由发布。所有自动导航、目录页、`ls`、`cd`、`open`、补全、搜索和 fastfetch 都使用这份模型；不再需要栏目注册或重复维护导航。

所有 frontmatter 字段均可省略；名称自动推导。`index.md` 代表目录，不产生 `/index` 条目；默认在正文下面显示直接 children，可用 `show_children: false` 关闭。`draft` 在开发和生产中均不发布，draft index 排除整个子树。`hidden` 保留直接 URL，但从导航、列表、补全、搜索、recent、统计和 RSS 排除；目录隐藏规则传递到 descendants。空目录可访问，只有草稿的目录不发布。正文和目录路径冲突以及系统保留路径会产生构建错误。

采用重新构建／部署更新生产内容的模式，不向用户 content tree 写回 generated 文件；开发阶段复用 Astro watcher，在页面请求时重算模型。About 和 Uses 为根 Markdown，Contact 为复用资料配置的 MDX，且修复了只有 GitHub／socials 时错误显示无联系方式的空态。既有主题、终端与搜索 UI、文章渲染和 mobile 组件继续复用。README 已记录文件树操作、默认规则、图片和部署流程。

本轮验收：**64 项单测、31 项生产浏览器回归、6 项开发浏览器测试全部通过**；最终 `npm run build` 的 Astro check 为 **0 errors、0 warnings、0 hints**。既有上游 MDX directive bundling warning 仍存在。`test:build` 在隔离副本连续三次构建，验证无 frontmatter 的 root 文档、`research`／`hobby`／`mycat`、generated／explicit index、`show_children: false`、空目录、任意嵌套、relative image、draft／hidden、增删后重建、root index、公开地址及只配置 GitHub 的 Contact。每次构建前后比较整个 content tree 的文件与目录快照，源码无写回。开发 fixture 在同一服务进程中验证新增、修改、删除后路由／导航／补全／搜索更新，并实际验证中文和带空格的文件名、`pwd` 及 `cd ..`。生产构建也验证这些文件名与 URL 路径一致。自动化验收之外的真实手机与真人辅助技术检查仍沿用原有待办。
